# SPEEDING 世界运行与叙事系统 TODO

## 开工前必读：Agent Hub 主版本线

本项目当前以 **Agent Hub 迭代为主线，Speeding 作为贯穿各版本的真实验收案例**。每次开始
开发前，必须先判断需求属于哪个阶段；未通过当前阶段退出门槛，不提前堆叠后续功能。

- **H0：清理平台与 Speeding 的耦合**
- **H1：Run 与通用状态**
- **H2：统一事件、工具结果与提示词合成**
- **H3：可控多跳协作**
- **H4：群组、频道和会议**
- **H5：工作流、审批和群体决策**
- **H6：情绪、认知、记忆和动态关系能力包**
- **H7：扩展系统及 Agent Hub 运营产品化**

开工检查：

1. 先说明本次工作属于 H0–H7 的哪个阶段；
2. 先实现不含 Speeding 领域词的 Agent Hub 通用能力；
3. 再用 Speeding 具体场景进行真实 Agent 验收；
4. 同时用一个非游戏场景反向验证，避免平台被游戏定制；
5. 世界观、账本、压力时钟、剧情和玩家 UI 留在 Speeding，不进入 Hub Core；
6. 完整优先级、版本退出门槛和当前批次以 `version-roadmap.md` 为准。

> 状态：设计待实现。本文是 SPEEDING 在 Zerone Agent Hub 之上的产品路线图，不代表现有 Agent Hub 已具备这些能力。

## 目标

把当前的 Agent 配置、结构化行为人格和点对点组织关系，扩展为可持续运行、可传播、可结算、可复盘的多人 AI 财富处置策略游戏。核心循环是：

```text
世界时钟推进
  → 到期事件进入队列
  → NPC 按知情状态感知事件
  → 人格、目标、关系和记忆共同决策
  → 调用工具或向其他 Agent 通信
  → 系统执行并返回结果
  → 产生传播、延迟结算、关系变化和新事件
  → 叙事导演调整节奏并进入下一回合
```

## 设计边界

- **世界事实与 NPC 认知分离**：事实只有一份，NPC 可以不知道、误解或持有过时信息。
- **人格与权限分离**：人格决定 Agent 想做什么；关系、工具和系统策略决定它能否执行。
- **模型与结算分离**：模型选择行动并生成表达；资金、舆情、法律和关系结果由确定性规则或受控概率结算。
- **关系表、MCP 与提示词分层**：关系表是事实来源，MCP 是能力入口，提示词只是当前状态的投影。
- **所有异步行为可追踪**：事件、消息、工具调用、预算消耗和结算结果必须拥有稳定 ID 与因果链。
- **所有系统可复盘**：同一局游戏必须能够按时间、事件、角色和因果关系回放。

## 建议实施顺序

### P0：世界运行底座

- [ ] **1. 世界时钟（World Clock）**
  - 定义游戏时间、现实时间与回合的换算关系。
  - 支持暂停、恢复、倍速、单步推进和管理员跳时。
  - 所有消息、事件、记忆与结算同时记录游戏时间和现实时间。
  - 同一个时间点的任务采用稳定排序，保证回放时结果一致。
  - 完成标准：暂停后不再产生自动行为；单步推进能够稳定重放同一批到期事件。

- [ ] **2. 事件队列（Event Queue）**
  - 统一承载世界事件、NPC 行动、消息投递、传播、会议、工具回调和延迟结算。
  - 事件信封至少包含 `event_id`、`game_id`、`occurred_at`、`scheduled_at`、`event_type`、`actor_id`、`subject_ids`、`root_event_id`、`parent_event_id`、`visibility`、`payload`、`idempotency_key`。
  - 支持优先级、重试、取消、超时、死信和幂等消费。
  - 完成标准：服务重启不会丢事件；重复投递不会造成重复扣款或重复改变关系。

- [ ] **3. 延迟结算与 Token 调度预算**
  - 行动可以立即发生，但影响允许在未来多个时间点逐步结算。
  - 每局、每回合、每个 Agent、每条因果链分别配置 Token、工具调用、消息跳数和并发预算。
  - 超出预算时进入排队、降级模型、摘要上下文或停止链路，不允许静默无限消耗。
  - 区分模型预算与游戏资源；有钱不能绕过平台 Token 上限，Token 不足也不能改变游戏规则。
  - 完成标准：能够解释一次行动消耗了多少预算、还剩多少、为什么被延迟或终止。

### P1：Agent 内在状态

- [ ] **4. 双层人格模板**
  - 保留结构化 `behavior_profile` 数值层，用于可测试的决策倾向。
  - 增加叙事层：原型、公开目标、私人目标、欲望、恐惧、禁忌、怪癖、语言风格和秘密。
  - 新建可版本化的人格模板；创建 Agent 时下拉选择，并允许单个 Agent 覆盖部分字段。
  - 部署时保存模板版本快照，避免模板更新静默改变正在进行的游戏。
  - 完成标准：相同场景可以对不同人格做重复测试，并得到可解释的选择差异。

- [ ] **5. NPC 知情状态（Knowledge State）**
  - 为每个 NPC 记录其知道、相信、怀疑和不知道的事实。
  - 状态至少区分 `known`、`believed`、`suspected`、`disputed`、`forgotten`，并记录置信度、来源、获知时间和保密级别。
  - Agent 只能收到符合身份、权限、传播路径和当前知情状态的世界快照。
  - 同一事实允许不同 NPC 拥有互相矛盾的理解，但不得修改世界事实本身。
  - 完成标准：未获知丑闻的 NPC 不会在提示词中看到该丑闻；谣言与已证实事实能够被区分。

- [ ] **6. 主观长期记忆**
  - 记忆保存参与者、事实引用、主观解释、情绪、重要度、可见性和来源事件。
  - 关系事件、会议、承诺、背叛、帮助与工具结果均可形成记忆。
  - 检索必须按 Agent、游戏、可见范围和时间过滤，再做语义相关性排序。
  - 记忆可以影响判断，不能直接授予工具、数据或通信权限。
  - 完成标准：NPC 能在后续场景中引用相关往事，并且无法回忆自己从未获知的信息。

### P2：行动、传播与协作

- [ ] **7. 工具执行结果反馈**
  - 采用“选择一个结构化行动 → 系统执行 → 返回结果与环境变化 → 再决策”的循环。
  - 工具结果至少包含成功状态、直接成本、公开影响、私下影响、产生的事件和下一次结算时间。
  - 结果进入事件队列、知情状态、关系事件和长期记忆，不能只返回一段聊天文本。
  - 完成标准：连续多步任务可以逐步执行；失败结果会真实改变 Agent 的后续计划。

- [ ] **8. 自主回合调度器**
  - Agent 可由世界时钟、事件、消息、目标到期或叙事导演触发，而不必等待玩家发言。
  - 仅在 Agent 空闲且预算充足时运行；支持冷却时间、最大回合、优先级、抢占和取消。
  - 每次运行生成 `run_id`，记录触发原因、输入快照、决策、工具调用与最终状态。
  - 完成标准：玩家不操作时世界仍能有限度推进，同时不会出现同一 Agent 并发自我冲突。

- [ ] **9. 传播渠道（Propagation Channels）**
  - 建模私聊、会议、内部邮件、董事会文件、公司公告、媒体、社交网络、监管披露和小道消息。
  - 每种渠道配置受众、延迟、可信度、泄漏概率、失真概率、追溯性和传播半径。
  - 传播更新的是 NPC 知情状态，并可继续产生二次传播事件。
  - 完成标准：同一消息通过私聊与公开声明传播时，到达范围、速度、可信度和后果明显不同。

- [ ] **10. 可控多跳消息**
  - 在现有有向关系和动作白名单基础上支持 `A → B → C`、回报与有限循环。
  - 消息信封增加 `conversation_id`、`root_message_id`、`parent_message_id`、`hop_count`、`max_hops`、`visited_agents`、`deadline`、`token_budget` 和去重键。
  - 人格决定是否尝试转发、越级或隐瞒；关系策略逐跳授权；运行时预算阻止消息爆炸和死锁。
  - 不再永久禁止嵌套投递，但同一同步调用栈内不得互相阻塞等待。
  - 完成标准：合法的 `A → B → C` 可以完成；`A → B → A → B` 会在预算或去重规则处可解释地停止。

- [ ] **11. 群组与成员（Group Foundation）**
  - 保留 `agent_relations` 作为 Agent 间的一对一、有方向权限边，不用关系边模拟多人组织。
  - 新增 `agent_groups` 与 `group_members`，表达组织、委员会、派系、常设团队和临时工作组。
  - 成员支持 leader、主持人、普通成员、观察员、外部来宾，以及加入时间、退出时间、任期和成员状态。
  - 群组支持公开、私密、仅邀请、临时有效期和嵌套组织；成员变更必须形成可审计事件。
  - 完成标准：可在管理端创建群组、配置成员和角色；同一 Agent 可加入多个群组且权限互不串联。

- [ ] **12. 群组频道、订阅与会议记录**
  - 新增 `group_channels` 与 `subscriptions`，支持公告、广播、共享讨论、专题频道和会议频道。
  - 增加群组消息、回复线程、会议、会议参与者、议程、发言顺序、私聊和会议纪要模型。
  - 频道消息必须保留发送者、可见范围、订阅快照、投递结果、回复链与来源事件，保证事后复盘。
  - 群组发送定义 `fanoutPolicy`：全员、仅 leader、按角色、轮询。
  - 群组回复定义 `aggregationPolicy`：全部回复、首个成功、leader 汇总、多数票、法定人数。
  - 回复披露定义 `replyVisibility`：公开给全组、仅发送人、仅 leader。
  - 群组不是把点对点消息简单广播给所有 Agent；每个成员仍按知情状态、关系、人格和订阅状态独立处理。
  - 完成标准：多人讨论不会同时无序回复；可查询每位成员是否收到、是否处理、回复对谁可见，并生成完整会议记录。

- [ ] **13. 工作流、审批与群体决策**
  - 新增 `workflows`、`steps` 与 `approvals`，支持顺序执行、并行执行、会签、投票、否决和超时升级。
  - 工作流步骤明确执行主体（Agent、角色或群组）、输入输出、前置条件、截止时间、重试策略和升级目标。
  - 群体决策定义 `decisionPolicy`：共识、多数票、加权票、一票否决。
  - 投票开始时冻结成员、角色与权重快照，防止投票过程中通过增删成员改变结果。
  - 审批记录同意、拒绝、弃权、理由、代理投票、超时和否决来源；所有状态变化进入事件队列。
  - 运行时与组织 MCP 增加 `group_send`、`channel_publish`、`workflow_start`、`approval_vote` 等受控入口。
  - 完成标准：可稳定完成串行交接、多人会签、法定人数表决、一票否决和超时升级，并能解释最终决策如何产生。

### P3：全局故事编排

- [ ] **14. 叙事导演（Narrative Director）**
  - 读取世界状态，但不直接代替 NPC 决策。
  - 管理章节、节奏、危机强度、伏笔、未解决矛盾、人物弧光、路线事件和结局条件。
  - 根据长时间无变化、冲突过密或关键角色掉线等情况，选择已有合法事件模板注入事件队列。
  - 对导演行为保留原因、规则版本和随机种子，保证复盘时可以解释。
  - 完成标准：一局能够形成数小时的起承转合，而不是连续随机事件或单纯聊天。

## 关键依赖关系

```text
世界时钟 ──→ 事件队列 ──→ 延迟结算与预算
                    ├──→ 自主回合调度器
                    ├──→ 传播渠道 ──→ NPC 知情状态
                    └──→ 工具结果反馈 ──→ 主观长期记忆

双层人格模板 ─┐
关系图谱 ─────┼──→ Agent 决策 ──→ 可控多跳消息 ──→ 群组与成员
知情状态 ─────┤
长期记忆 ─────┘

群组与成员 ──→ 频道与订阅 ──→ 群组消息与会议记录
                                  └──→ 工作流、审批与群体决策

以上全部 ──→ 叙事导演
```

## 暂不纳入本轮实现

- 不让 LLM 直接修改余额、舆情、法律状态或关系分数。
- 不把所有世界状态无差别塞进每个 Agent 的上下文。
- 不用“向所有 Agent 广播”冒充群组或会议。
- 不在缺少因果 ID、跳数和预算时开放无限 Agent 转发。
- 不把叙事导演做成无权限限制的超级 Agent。
