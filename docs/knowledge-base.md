# Agent Hub 知识库

Agent Hub 提供知识库、文档、解析配置、切片、检索和数据源管理。桌面端提供完整管理入口；H5 支持知识库与文档操作、上传、解析状态、检索及来源查看。Agent 通过绑定的知识库调用 MCP 工具，不能借此访问未授权的知识库。

浏览器和移动端统一访问 Hub 的 `/api/v1/admin/knowledge` 网关。知识库服务地址与凭据通过 `MULTIRAG_BASE_URL`、`MULTIRAG_API_KEY` 配置，只保存在服务端。原生记忆有独立的应用和身份边界，见[原生记忆接入](memory/README.md)。

## 模型与实例绑定

知识库可使用嵌入、OCR、视觉和重排模型。模型的显示名称与提交身份分开：`reference` 是不透明字符串，可能是超过 JavaScript 安全整数范围的十进制 ID；`fullId` 承载选择器实际提交的模型引用。调用方应原样保存和传递，不能转成数字、按显示名称重建，或给数值引用追加厂商后缀。一个模型支持多个能力时，可分别出现在对应候选列表中；禁用的模型或实例不能作为新选择。

从 Hub 供应商配置同步知识库模型时，Hub 为该供应商与服务凭据作用域持久绑定明确的模型实例。首次登记先保留实例身份，再提交所选模型；后续同步读取并操作同一实例，不按同名模型接管其他实例。更换知识库服务凭据属于不同认证作用域，不会自动继承旧绑定。

- 连接检查不创建绑定或模型实例。连接检查或登记成功，不表示每个模型、每种能力都已完成实际推理。
- 同步成功需要独立读取模型库存并确认身份、能力和配置，HTTP 200 本身不足以确认。
- 已有模型的能力或上下文声明不一致时，同步明确失败，不删除重建被引用模型。
- 创建响应丢失后，仅按已保留的实例身份读取核对；读不到不授权再次创建。凭据更新结果不明时保留处理中状态，由管理员核对实际实例与原请求后处理，不自动重放或清除占用状态。

实例绑定记录保存在 `provider_multirag_bindings`，包含身份、配置摘要及同步状态，不保存明文密钥。删除 Hub 供应商只移除本地绑定回执，不请求删除模型服务中的模型。Hub 自身的直接模型调用与知识库模型实例分别管理。

## 文档、解析与表格

文档上传与启动解析是两个步骤。上传成功后保留文档 ID；提交解析只表示请求已受理，应继续查看文档状态、进度和切片数。解析失败后可保留原文，修改允许的参数，再明确发起解析。

知识库默认解析配置与单文档可编辑参数具有不同范围：

| 配置位置 | 能力与约束 |
| --- | --- |
| 知识库设置 | 选择解析方式、布局模型、分块、元数据、父子块、图谱和 RAPTOR 等配置。图谱配置可选择 NER 并设置执行预算；RAPTOR 可设置树构建与聚类参数。 |
| 单文档编辑 | 只提交文档更新接口允许且实际修改的字段，不回传完整存储快照。知识库级表格列角色、NER、图谱预算和 RAPTOR 扩展不通过单文档 PATCH 修改。 |
| 逐文件上传 | 文件可继承知识库表格默认值，也可通过 multipart `parser_config` 设置该文件的 `table_column_mode` 与 `table_column_roles`。不提交列名库存或任务内部覆盖状态。 |

表格列用途包括 `indexing`（参与索引）、`metadata`（文档元数据）和 `both`。列名保留原始字符，包括点号和前后空格。可读取表头时从表头选择；受限 UTF-8 CSV 支持本地表头预览，其他文件可手动填写列名或使用继承、自动模式。手动列名需要与实际资料核对，界面不会猜测工作簿表头。

`table_column_roles` 是完整替换映射；移除键表示移除该列的指定用途，`{}` 表示清空映射。其他可深合并的解析对象仍按字段补丁处理。兼容的 `parser_config.ext` 在保存时展开到顶层，同名字段由 `ext` 覆盖；保存后按规范化配置独立读回。已有逐文件覆盖不会因知识库默认值改变而被重新分类。

切片页可核对文本、关键词、问题、标签、图片和启用状态。支持的原文类型可直接预览；PDF 引用使用从 1 开始的页码和原文位置坐标，无法确认的位置不推测。原文和图片读取仍执行当前身份与知识库范围检查。

## 检索与来源

检索支持知识库、文档和元数据范围，以及关键词、语义、混合、融合和可选重排模型。桌面检索可联合选择知识库；MCP 可选择 `joint` 联合检索或 `per_dataset` 分别检索。联合检索要求兼容的嵌入模型实例，分别检索不将不同知识库的分数合并排名。某个范围失败时，不用不完整结果冒充整体成功。

- `top_k` 表示候选池大小，`page` 与 `size` 表示结果分页。知识库目录和文档目录的单页请求最多 100 条；取得完整目录时需逐页读取。
- `total` 是检索服务返回的统计，不是当前页 `chunks.length`，也不是知识库文档总数。它可能受检索路径和候选池影响，不能据此承诺所有计数结果都可翻页获取；MCP 分库模式的统计与分页按库独立计算。
- 未传文档范围表示不限文档；明确传入 `doc_ids: []` 表示空范围，不扩大为全库。文档条件与元数据命中取交集。
- `search_id` 指向有权使用的已保存搜索配置，其元数据配置可能覆盖请求中的筛选配置。非空 `search_id` 或受限文档、元数据范围不能与不支持这些范围的图谱检索组合。
- `similarity` 是排序分，允许大于 1；它不是概率。`vector_similarity`、`term_similarity` 等未计算分项保留 `null`，真实零分仍为零，界面不将缺失分数补成零。

结果必须能确认所属知识库与文档；身份别名不一致或结果越界时隐藏结果并报错。检索表单保留上次执行的问题与范围，修改草稿不会让旧结果变成本次请求的结果。元数据操作符只开放能够保持明确范围语义的用法。

## 停止解析与写入恢复

停止解析会请求取消任务，并清理部分解析切片及计数。桌面单文档、批量操作和 H5 均需先确认此副作用；文档原文保留，可重新解析。请求受理后刷新文档、知识库计数与切片；受理回执不等于后台任务已终止。

| 场景 | Hub 的恢复方式 |
| --- | --- |
| 部分文件上传成功 | 保持失败语义，只保留经归属与独立读回确认的 `data.uploaded` 文档 ID。客户端核对请求文件后，仅重传剩余文件；已确认文件不会因为解析或刷新失败而重传。 |
| 上传结果未知 | 先刷新文档目录并核对队列，再由用户明确决定剩余文件的重试。不按超时、数组位置或同名文件推断成功。 |
| 解析或刷新失败 | 继续使用已确认文档 ID，分别恢复解析或状态读取，不重新上传。 |
| 切片图片写入不明 | 保留受限的 `stage`、`outcome`、`index`、`image`、`image_id`、`retry_safe` 回执和编辑草稿。`retry_safe=false`、部分或未知结果禁止盲目再次创建、追加或更新；只读核对入口始终可用。 |

切片保存需读取实际内容；带图片的写入还需核对受保护图片内容。核对发现不同结果时，可查看已保存结果后重新编辑，或明确放弃草稿返回列表。需要再次写图片时使用明确的替换操作，不能因响应丢失重复追加。恢复回执不向客户端暴露凭据、文件内容或内部错误堆栈。

## 连接器配置与任务控制

连接器可关联一个或多个知识库，并分别设置是否自动解析。来源覆盖对象存储、协作应用、邮件、数据库与 REST API 等类型；界面按来源提供配置字段说明和示例，完整配置与凭据由服务端验证。S3 兼容存储使用 `source=s3` 与 `bucket_type=s3_compatible`，不是单独的连接器来源。

同步与删除清理具有独立周期，均使用非负整数分钟：

- `refresh_freq=0` 关闭定时同步；恢复操作仍可能立即启动一次任务。
- `prune_freq=0` 关闭定时清理。删除清理仅在来源支持且 `sync_deleted_files` 开启时运行，不负责导入新文档。
- 重新调度会取消运行中或待执行任务，并按保存配置重新调度同步及已启用的清理任务，影响该连接器关联的所有知识库。
- 日志区分 `sync` 与 `prune`，分别查看新增文档、删除数量和错误。HTTP 成功、周期保存和任务完成是不同状态。

删除同步默认关闭。目录分页、权限、读取或取消不完整时，不把部分库存当成完整删除依据。数据源账号、查询或范围变化可能要求重建；邮箱和关系数据库的按知识库游标由任务管理，编辑器不回写旧游标。

保存连接器后独立读取配置；读回失败时保留恢复状态，不报告保存成功。关闭再打开编辑器会重新读取配置，避免旧周期或凭据覆盖较新的配置。解除知识库关联会停止该绑定的任务，不删除已导入文档；重建、删除连接器与删除文档是独立操作。
