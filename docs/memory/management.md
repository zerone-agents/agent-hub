# 原生记忆管理

AgentHub 管理业务应用内、指定用户及账户生命周期的记忆。底层使用底层记忆模块原生记忆库、自动抽取、类型及消息启停接口；管理员通过获委托 Hub 租户的后台 JWT 操作。应用服务令牌不授予后台管理权限，页面也不接受调用方任意指定底层 bank、user、agent 或 session。

## 能力与管理范围

| 管理对象 | 底层记忆模块原生能力 | Hub 当前接法与边界 |
| --- | --- | --- |
| 应用记忆库 | 查看名称、类型、模型、权限、容量、抽取配置；原生 API/Web 提供全局设置 | 应用固定绑定专用私有 bank；只读展示白名单配置，不开放全局编辑 |
| 记忆记录 | RAW 原文及 semantic、episodic、procedural 派生记录 | 按业务用户/生命周期查看，提供列表筛选、分组、详情及来源追溯；派生文本仍是模型输出 |
| 单条启停 | 标准消息 `status` 开关 | 修改记录自身开关；原文停用会在 Hub 供给时阻断其派生记录，不逐条改写子记录 |
| 来源与时间 | `source_id`、原生 session、有效/失效时间字段 | 核验同一范围及父原文；原生 session 是写入批次标识，不冒充 Runtime 会话 ID；事件起止时间不统一当 TTL |
| 抽取进度 | 原文列表附带后台任务信息 | 区分已受理、处理中、已有派生、完成、失败及未知；已有派生不等于任务完成，不提供盲重提或伪造重试成功 |
| 召回诊断 | 原生搜索接口及标准检索参数 | 单独查看经来源校验的原生命中；保留结果顺序，不制造相似度分数 |
| 聊天供给 | 使用原生记忆搜索 | Hub 另补最近原文、实施上下文预算，并提示按较新明确纠正理解历史冲突 |
| 列表统计 | 原生列表及配置字段 | 统计当前所选用户/生命周期已读到的记录；正文筛选属于 Hub 列表处理，不称为底层全库全文搜索 |
| 全局模型、权限与提示词 | 原生配置接口存在相关字段及编辑能力 | Hub 本期不开放 bank 级模型、权限、类型、容量、提示词修改，不把用户管理操作扩展为全局变更 |
| 单条遗忘 | 原生 DELETE 消息接口写入 `forget_at`，检索默认排除此条 | 仅对已核验范围的记录操作，独立读回遗忘标记；列表保留记录，不提供恢复；与可恢复的启停分开 |
| 物理删除与账户清理 | 删除 bank 等接口存在 | 不开放物理清理、撤权或注销删除闭环 |

`memory_size` 表示配置的容量上限，不是已用字节或记录数，页面不据此推算使用率。容量策略可展示为配置值；底层容量淘汰与用户主动遗忘是不同机制，不能因 Hub 未开放删除便承诺永久保留全部记录。

原生字段存在不代表当前运行链路已执行：当前异步抽取调用使用默认提示词组装，保存的 `system_prompt` / `user_prompt` 未传入该调用；`LRU` 枚举也不能作为实现已生效的证明。具体原生消费者审计见[适配器说明](../../internal/infrastructure/nativememory/README.md)。

## 自身开关、父状态与实际可用状态

| 返回字段 | 含义 |
| --- | --- |
| `nativeStatus` | 该记录在底层记忆模块中自身的启用开关；启停请求以它作为当前状态 |
| `forgottenAt` | 本条原生遗忘标记的时间，存在时正常检索排除此条 |
| `parentForgottenAt` | 派生记忆的父原文遗忘时间；Hub 因此停止供给，但不代表本条已被逐条遗忘 |
| `parentStatus` | 派生记录的 RAW 父原文当前是否可用；RAW 本身不带此字段 |
| `status` | Hub 实际供给状态：自身启用、未遗忘，且派生记录的父原文也可用 |
| `statusChangeAllowed` | 是否允许通过本次管理接口改开关；目标或父原文已遗忘时禁止操作 |

停用一条派生记忆不影响父原文及兄弟记录。停用 RAW 原文后，Hub 后续检索和聊天上下文均不供给它及其派生内容，但派生记录自身开关保留。恢复父原文后，仅自身仍启用的子记录恢复可用，曾被单独停用的子记录不会被强制开启。父原文仍停用时，不能开启一个已停用的子记录。

启停不删除正文、来源、向量或历史对话，不暂停已经排队的抽取，也不撤回已读取上下文的在途回复。迟到派生可能仍以原生启用状态写入，Hub 会继续核验父原文。这里的父子阻断是 Hub 的供给规则，不承诺底层记忆模块其他直接消费者也执行相同级联规则。

## 后台接口

以下路径均以 `/api/v1/admin/memory` 为前缀，需要管理员或维护者角色以及对应应用的 Hub 租户委托。未知 JSON 字段、越权应用及非法范围会被拒绝；记录操作还要求当前生命周期有效。

### 只读应用配置

`GET /native-config?tenantId=…&applicationId=…`

只接受这两个单值查询参数；不接受 bank 覆盖、用户参数或重复参数。返回名称、描述、类型、存储类型、聊天/向量模型引用、权限、容量上限、容量策略、温度及创建时间。模型可能是数字字符串引用，不保证为可读模型名称。合法的零温度保留为零。

返回 DTO 不包含凭据、提示词正文、原生所有者映射或任意完整配置。实现：[管理 DTO](../../internal/memory/management_types.go)、[原生白名单读取](../../internal/infrastructure/nativememory/management.go)。

### 单条启停

`PATCH /native-messages/{messageId}`

```json
{
  "scope": {
    "tenantId": "synthetic-tenant",
    "applicationId": "synthetic-app",
    "userId": "synthetic-user",
    "accountLifecycleId": "synthetic-lifecycle"
  },
  "enabled": false,
  "expectedEnabled": true
}
```

两个状态字段都必须是明确的布尔值，`false` 不能按缺失处理；消息 ID 必须是规范的正 int64 十进制字符串。服务先校验应用与生命周期，再核验原生目标及父来源，修改自身开关并独立读回状态、正文、类型及来源。

- `409`：观察到的自身开关与 `expectedEnabled` 不符，或开启子记录时父原文仍停用；刷新后重新核对。
- `503 / memory_outcome_unknown`：写入结果无法确认；先读回列表，不把超时或 HTTP 成功当作状态已生效。
- `501`：当前应用或目标不支持此操作；不降级为删除或清理。

`expectedEnabled` 是观察状态的前置条件。原生 PUT 没有跨系统原子版本锁，不能将它描述为与外部 Web 写者之间的原子 CAS。审计记录操作、规范消息 ID、目标摘要及请求状态，明确保留 `false`；不记录聊天正文、检索问题或凭据。

### 单条遗忘

`POST /native-messages/{messageId}/forget`，请求体为 `{ "scope": { "tenantId": "…", "applicationId": "…", "userId": "…", "accountLifecycleId": "…" } }`。要求 `nativeForgetSupported=true`、获委托管理角色、当前生命周期有效，以及目标和父来源匹配。此能力与旧事实删除接口的 `forgetSupported` 独立，不能据此调用物理删除/撤权接口。

服务调用底层记忆模块的 `DELETE /api/v1/messages/{memoryId}:{messageId}`，该接口只写入 `forget_at`。读回同一范围的正文、类型、来源、会话及遗忘标记后才确认成功；响应丢失不会盲重发，已有标记的重复请求只读返回。无法核对时返回 `503/memory_outcome_unknown`，页面提示刷新检查，不展示成功或自动重试。

原文与派生记录分别遗忘，不宣称底层级联。遗忘原文后，Hub 同时阻断其派生供给，但派生记录没有被逐条打标，其他直接消费者仍需自行处理父来源。管理列表展示“已遗忘”“来源已遗忘”和遗忘时间；已遗忘记录不能通过启用开关恢复。确认框明确当前操作不可撤销、内容保留、物理删除及备份清理未完成。停用和遗忘都会清除此前的召回展示并拒绝展示操作前迟到的召回结果；已发出或在途回复不被撤回。

### 原生召回与聊天供给

`POST /native-search` 接受 `{scope, query, limit?, similarityThreshold?, keywordWeight?}`。问题须为非空文本且不超过 2000 Unicode code points；`limit` 为 1～20，默认 5；阈值及关键词权重为 0～1，默认分别为 0.2、0.7。合法的零原样透传，返回 `options` 表示请求参数。

此接口只返回原生实际命中，按原生顺序展示，并核验目标及父原文。为校验而读到的父原文不会被附加为命中，也不会写入新聊天或触发抽取。

当前本地 Milvus 消费链只执行 dense 向量搜索，未执行相似度阈值过滤、关键词表达式及融合权重。参数正确透传不证明这些调参已影响排序；页面不提供这两个无效调参控件。其他存储引擎需分别验证，Hub 也不补造原生 DTO 未提供的分数。

`POST /native-context` 则是聊天供给：在原生命中之前优先补入最近两条可用 RAW 原文，默认最多 5 条，允许 1～20 条；总正文最多 4000 Unicode code points，超预算整条不供给并返回 `budgetLimited`。因此它与纯原生诊断可能返回不同记录或顺序。自然语言纠正提供更新的来源证据，不承诺自动消除所有旧派生冲突。

实现：[管理服务](../../internal/memory/management.go)、[管理路由](../../internal/handler/memory_management.go)、[聊天供给](../../internal/memory/conversations.go)。

## 验证与界面约定

自动化检查见 [验证指南](validation.md)。后台合同覆盖权限、严格字段、零值、未知结果与审计；原生适配测试覆盖独立读回、来源与父状态。真实服务验收需要独立的合成数据环境，不能用 mock 结果替代。

页面沿用现有 Agent 与知识库管理页的标题、控件、主题色及 `pageIn .35s ease` 入场动画，尊重减少动态效果偏好。应用与账户在工具栏选择，数据按源原文分组，正文、来源和配置使用详情抽屉；不以持久统计卡片挤占记录区。统计仅表示当前账户范围，不代表整个记忆库的使用量。

## 动态应用

通过 [租户应用管理 API](applications.md) 创建并确认绑定的应用，会立即出现在获委托后台租户的应用列表中。创建及应用启停使用独立的服务端管理凭据；普通应用令牌没有管理权限。停用会阻断之后的业务请求，后台仍可查看已有数据，不代表删除或遗忘。
