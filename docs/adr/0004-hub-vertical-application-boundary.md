# ADR-0004：Agent Hub、能力包与垂直应用的代码边界

- 状态：Accepted for H0
- 日期：2026-09-12
- 关联协议：`agenthub.extension/v1alpha1`

## 背景

Speeding 是 Agent Hub 的首个高强度验收案例，但不是 Hub 的产品定义。过早拆成多个物理
仓库会增加联调成本；把游戏规则写入 Hub 又会阻碍平台独立运营。

## 决策

先实行逻辑与发布边界，接口稳定后再决定物理拆仓。

### Agent Hub Core / Organization Runtime

只包含跨行业成立的能力：Agent 身份、权限、Run、通用状态、事件、审计、关系合同、
消息、多跳、群组、频道、会议和工作流。Core 源码、数据库列、默认提示词和 UI 文案不得
包含 Speeding 世界语义。

### Capability Package

包含可选择安装的 Schema、事件、工具、关系语义、提示词片段、声明式 UI 和 reducer。
安装、启用、绑定分离；包不能绕过 Core 权限。通用包至少还要通过一个非游戏案例验证，
否则暂留应用命名空间。

### Vertical Application

拥有玩家/业务用户旅程、世界事实、领域规则、内容、结算和专属 UI。Speeding 拥有财富、
舆情、政治影响、剧情、虚拟时钟、胜负和复盘评分。垂直应用只能通过稳定 API/MCP/事件
协议使用 Hub，不直接写 Hub 数据库。

### Template

模板只生成配置或初始化数据，不执行逻辑、不注册工具、不授予权限。包含 reducer、远程
调用或事件消费的内容必须是能力包，不能伪装成模板。

## 仓库与发布策略

- H0–H3 可位于同一 Git 工作区，但模块目录、数据库迁移、API 和版本号保持独立。
- Hub CI 必须在不安装 Speeding 包时通过并可启动。
- Speeding 回归作为消费方契约测试运行，不成为 Hub 单元测试的领域依赖。
- 物理拆仓触发条件：扩展协议稳定、有独立发布节奏，或权限/团队所有权需要隔离。

## 提炼门槛

一个 Speeding 能力只有同时满足以下条件才提升为通用包：

1. 能用平台中性语言命名；
2. 至少一个非游戏场景具有相同语义；
3. 不依赖 Speeding 状态或 UI；
4. 权限、生命周期和失败语义可独立定义。

## 明确不做

- 不因 Speeding 当前急需而向 Core 添加领域字段。
- 不把 MCP 当作数据所有权边界；MCP 只是执行适配器。
- H0 不强制物理拆仓，也不搭建通用插件市场。
