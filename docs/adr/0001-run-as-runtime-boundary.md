# ADR-0001：Run 是动态运行的隔离边界

- 状态：Accepted for H0
- 日期：2026-09-12
- 关联协议：`agenthub.extension/v1alpha1`

## 背景

同一个 Agent 会参与游戏、研究任务和企业协作。人格、关系权限等长期配置可以复用，
但情绪、任务进度、对他人的临时态度和应用状态不能跨任务污染。目前用自由字符串
`scope` 表示场景，无法提供生命周期、版本锁定和可靠复盘。

## 决策

Agent Hub 将 **Run** 定义为所有动态执行数据的最小隔离边界。

- Run 具有 `draft → running ↔ paused → completed → archived` 生命周期；终态不可恢复执行。
- `run_agents` 绑定长期 Agent，但不复制或修改 Agent 本体。
- Run 开始时锁定参与 Agent、能力包、Schema、提示词片段和关系合同的版本快照。
- 动态状态、事件、消息因果链、预算和运行日志必须携带 `tenant_id + run_id`。
- Agent 的模型、知识库、职责和人格模板属于长期配置；执行时读取 Run 已锁定快照。
- 同一 Agent 可以同时进入多个 Run，运行数据不得互见，除非显式调用获授权的跨 Run 工具。
- `scope` 可保留为业务标签，但不能替代 `run_id` 或承担权限边界。

## API 与数据约束

- 创建 Run 不自动启动；启动操作完成快照并具有幂等键。
- `completed` 后拒绝状态写入、事件派生和新 Agent 消息，只允许查询与归档。
- 删除 Agent 或模板不能破坏历史 Run；历史快照与审计记录按保留策略存续。
- H1 可先实现单数据库事务，不要求分布式工作流引擎。

## 结果

Speeding 的一局游戏、研究团队的一次报告任务都使用相同 Run 模型；游戏回合、章节、
胜负和虚拟时间仍由 Speeding 扩展定义，不进入 Run Core。

## 明确不做

- 不把 Run 等同于聊天会话；一个 Run 可以有多个线程和会议。
- 不在 Core 内置游戏时钟、回合或存档槽。
- 不允许把动态情绪写回 Agent 或人格模板。
